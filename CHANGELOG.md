# Changelog

## Unreleased

- Sentinels are gone: the Sentinels page, the `/api/sentinels` routes, `alice sentinels` and the `sentinel-*` commands, the PR lock comments, `/alice` comments on PRs Alice didn't open, and `ALICE_FEATURE_SENTINELS`, `ALICE_SENTINEL`, `ALICE_SENTINEL_MS` and `ALICE_OWNER`. On first start, Alice archives the job cards sentinels made; their history keeps the status they had. `/alice` comments on a card's own PR still send it back.
- GitHub pull request mode is always available. The `ALICE_FEATURE_PULL_REQUESTS` switch is gone, along with the notices and `feature_off` answers for when it was off. A board stored as GitHub pull requests now integrates that way again.
- A Failed card whose pull request someone fixes and merges on GitHub now goes to Done. Before, only Review cards were settled from their PRs, so it stayed Failed. While its PR is open, Alice records the PR's state but starts no fix or conflict-repair runs for it.
- Auto-review no longer blocks automatic pull requests: a card the agent reviewer hands to a person, or sends back too often, gets a draft pull request with its findings, and a requested rerun waiting for a free run slot shows as Rerun queued instead of waiting on you.
- `alice tui` now looks like the web board and fills the terminal: lanes side by side, one tile per card with its title and one live fact, a spinner on running cards, and the card opening as a dialog over the board with its description and attempts. A sidebar numbers the boards (`1`–`9` open one) and `0` opens Today across every board; the header shows the board's spend and merge conflicts, and failure reasons and Needs you sit on coloured pills. It redraws only the rows that change, and takes the mouse: click a card to select it and again to open it, click boards, Today rows, tabs and footer keys, and scroll with the wheel. `r` moves a card to Ready without asking, even with pickup on; only a card the text check flags still asks. `/` finds a card by title or id, on the board or, from Today, on every board, and enter opens it.
- The attempt after a run timeout continues the timed-out Pi session with a short message ("You ran out of time on the previous attempt…") asking it to finish the remaining work and write its report, instead of sending the whole task again, so the agent picks up where it stopped. If the session file is gone it starts a fresh session with the whole task.
- A file that conflicts on 3 or more cards within 14 days gets a notice on its board, counted from merge failures and conflict-repair runs. It suggests a structural fix: `merge=union` in `.gitattributes` for append-only files, generating the file, or ordering the cards that touch it with dependencies. **Dismiss** hides it until the file conflicts again.
- Closing a card without merging asks why: duplicate, wrong approach, not needed, superseded, or other with a note. One click picks a reason and closes the card; skipping still closes it. `alice close CARD --reason duplicate` and the iOS app do the same. The reason shows in the card's history, and Statistics has a **Closed without merging** count by reason.
- A machine-wide limit on agents at once covers card runs and agent reviews on every board. It defaults to a quarter of the CPU cores, and you set it in **Settings > General** or with `alice agents N|auto`. Automatic work waits for a slot; a run you start yourself always starts. Boards within their own concurrency could together run 11 agents and their test suites, which stalled the machine and the server.
- When a card merges, cards in Review that depend on it are brought up to date with main, keeping their uncommitted work, and agent review runs again on the result. One that would conflict is left unchanged and shows the merge conflict instead of surprising you at Approve.
- The server stays responsive on a busy machine. The 2-second pickup tick found its candidates with one board rebuild per Ready card (880 ms on a 29-card queue, now 17 ms), and the auto-review tick checked externally merged cards with blocking Git. Card lookups no longer total every run on the board, and Ready cards skip loading boards.
- Spend limits (the daily start limit, the daily cost budget and the agent reviewer's diff caps) sit behind one **Limits** switch per board, off by default, in the board settings or `alice limits on|off`. Stored values are kept while it's off. Concurrency and loop guards (send-back, CI-fix and retry caps, the run timeout) always apply. Every limit is decided in `server/repo-limits.ts`. Existing boards start with limits off.
- A failed automatic run no longer pauses pickup. Its card waits in Failed, pickup never restarts it, and the next Ready card starts. Only an authentication or billing refusal from the provider still pauses pickup, since every card would fail the same way. Boards paused for a failed run resume on startup.
- Moving a Triage card to Ready checks its text first. A card that asks for something only a person can do (a physical device, screenshots by hand, staging or production) or never says what done looks like shows its flags with **Edit** and **Ready anyway**; nothing is blocked. `alice ready` prints the flags and needs `--yes` to move a flagged card.
- `alice open [CARD_ID]` opens the board, or a card by its short ID, in the browser and prints the URL. `--print` prints without opening.
- A run that seems to be going in circles shows **May be stuck** on its card and sends a browser notification, long before the run timeout. Alice flags a run that repeats one tool call 5 times in its last 20 calls, changes no files for 25 turns after it started changing them, or changes nothing in its first 60 turns, and asks the agent once to step back and try another approach. The flag clears when the run changes files again.
- Ten minutes before the 60-minute run timeout, Alice tells a run still going to stop starting new work and write its report with evidence attached. A run that settles in time reaches Review with that report instead of being killed without one.
- The agent reviewer now gets the implementer's report and the paths of the card's attachments. It opens attached screenshots and judges them, instead of handing a card to you for screenshots it couldn't see.
- Cards record where they came from: `ui`, `cli`, `plan`, `follow-up`, `sentinel`, `pr-comment`, or the agent name an API caller sends as `source` (`alice create --source hermes`). The Details tab shows it. Existing cards whose key prefix names their path (`hermes:`, `plan:`, `follow-up:`, `sentinel:`, `request:`) are backfilled once; the rest stay `manual`.
- Unattended review never merges into local main. On a local board an agent-approved card waits for your Approve; pull-request boards still open the PR. The verification command, the merge limit, `alice board --merge-limit` and `scripts/verify.sh` are gone.
- The agent reviewer runs the repository's checks itself instead of sending a card back for missing proof. Checks only a person can do, such as device runs, screenshots or staging, go to you.
- Browser notifications now use Web Push: turn on **Notify this browser when a card needs you** in Settings and you get one when a card becomes your turn or fails, even with no Alice tab open. Clicking it opens the card. It replaces the old Review notification, which only fired while a board page was open. Needs HTTPS or localhost.
- **Approve and update PR #N** pushes to the open PR without a confirmation prompt. Approving a merge into local main still asks first.
- Alice's commits and merges (Approve, pre-push checks at Review, CI fix merges) use your Git name and email instead of `Alice <alice@localhost>`, so a commit signed with your key shows as verified. Alice's identity is now only a fallback for repositories with none configured.
- `ALICE_METRICS=1` serves Prometheus metrics on `/metrics`: runs, outcomes, run time, spend and tokens per repository and model, agent reviews, cards per lane and active runs. They're read from the database on each scrape, so totals survive restarts. See docs/metrics.md.
- Pull-request boards draft the PR and run the repository's commit and pre-push hooks when a run reaches Review, so Approve and open PR opens the dialog with the draft ready and pushes without running the hooks again. A hook that fails at Review goes back to the agent before you review, up to 2 times in a row.
- `scripts/install-desktop.sh` keeps a Mac's Alice.app built from `origin/main`, rebuilding only when desktop code changed; `--launchd` runs it every hour.
- Sentinels and GitHub pull requests are now optional build features, both off by default. Turn them on with `ALICE_FEATURE_SENTINELS=1` and `ALICE_FEATURE_PULL_REQUESTS=1` when building and starting Alice; stored data is kept, and Approve never merges locally in place of a required pull request. See docs/reference.md.
- `alice` has a new help screen with a cake, per-command help (`alice help start`), typo suggestions, and aligned, coloured output on a terminal. Piped output is unchanged. `npm link` puts it on your `PATH`.
- `alice doctor` names the server it reached, says whether it's local or remote, and prefixes remote board paths with the host. A missing `pi` now reads as not found when a directory on `PATH` is unreadable.
- `alice doctor` ends with `INFO` rows: the CLI's path, its `ALICE_*` variables with secrets hidden, and the server's host, features, active runs, agent models, telemetry and Discord webhook state.
