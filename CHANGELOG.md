# Changelog

## Unreleased

- A machine-wide limit on agents at once covers card runs and agent reviews on every board. It defaults to a quarter of the CPU cores, and you set it in **Settings > General** or with `bakery-cli agents N|auto`. Automatic work waits for a slot; a run you start yourself always starts. Boards within their own concurrency could together run 11 agents and their test suites, which stalled the machine and the server.
- The server stays responsive on a busy machine. The 2-second pickup tick found its candidates with one board rebuild per Ready card (880 ms on a 29-card queue, now 17 ms), and the auto-review tick checked externally merged cards with blocking Git. Card lookups no longer total every run on the board, and Ready cards skip loading boards.
- Spend limits (the daily start limit, the daily cost budget and the agent reviewer's diff caps) sit behind one **Limits** switch per board, off by default, in the board settings or `bakery-cli limits on|off`. Stored values are kept while it's off. Concurrency and loop guards (send-back, CI-fix and retry caps, the run timeout) always apply. Every limit is decided in `server/repo-limits.ts`. Existing boards start with limits off.
- A failed automatic run no longer pauses pickup. Its card waits in Failed, pickup never restarts it, and the next Ready card starts. Only an authentication or billing refusal from the provider still pauses pickup, since every card would fail the same way. Boards paused for a failed run resume on startup.
- Moving a Triage card to Ready checks its text first. A card that asks for something only a person can do (a physical device, screenshots by hand, staging or production) or never says what done looks like shows its flags with **Edit** and **Ready anyway**; nothing is blocked. `bakery-cli ready` prints the flags and needs `--yes` to move a flagged card.
- `bakery-cli open [CARD_ID]` opens the board, or a card by its short ID, in the browser and prints the URL. `--print` prints without opening.
- A run that seems to be going in circles shows **May be stuck** on its card and sends a browser notification, long before the run timeout. Bakery flags a run that repeats one tool call 5 times in its last 20 calls, changes no files for 25 turns after it started changing them, or changes nothing in its first 60 turns, and asks the agent once to step back and try another approach. The flag clears when the run changes files again.
- Ten minutes before the 60-minute run timeout, Bakery tells a run still going to stop starting new work and write its report with evidence attached. A run that settles in time reaches Review with that report instead of being killed without one.
- The agent reviewer now gets the implementer's report and the paths of the card's attachments. It opens attached screenshots and judges them, instead of handing a card to you for screenshots it couldn't see.
- Unattended review never merges into local main. On a local board an agent-approved card waits for your Approve; pull-request boards still open the PR. The verification command, the merge limit, `bakery-cli board --merge-limit` and `scripts/verify.sh` are gone.
- The agent reviewer runs the repository's checks itself instead of sending a card back for missing proof. Checks only a person can do, such as device runs, screenshots or staging, go to you.
- Browser notifications now use Web Push: turn on **Notify this browser when a card needs you** in Settings and you get one when a card becomes your turn or fails, even with no Bakery tab open. Clicking it opens the card. It replaces the old Review notification, which only fired while a board page was open. Needs HTTPS or localhost.
- **Approve and update PR #N** pushes to the open PR without a confirmation prompt. Approving a merge into local main still asks first.
- Bakery's commits and merges (Approve, pre-push checks at Review, CI fix merges) use your Git name and email instead of `Bakery <bakery@localhost>`, so a commit signed with your key shows as verified. Bakery's identity is now only a fallback for repositories with none configured.
- `BAKERY_METRICS=1` serves Prometheus metrics on `/metrics`: runs, outcomes, run time, spend and tokens per repository and model, agent reviews, cards per lane and active runs. They're read from the database on each scrape, so totals survive restarts. See docs/metrics.md.
- Pull-request boards draft the PR and run the repository's commit and pre-push hooks when a run reaches Review, so Approve and open PR opens the dialog with the draft ready and pushes without running the hooks again. A hook that fails at Review goes back to the agent before you review, up to 2 times in a row.
- `scripts/install-desktop.sh` keeps a Mac's Bakery.app built from `origin/main`, rebuilding only when desktop code changed; `--launchd` runs it every hour.
- Sentinels and GitHub pull requests are now optional build features, both off by default. Turn them on with `BAKERY_FEATURE_SENTINELS=1` and `BAKERY_FEATURE_PULL_REQUESTS=1` when building and starting Bakery; stored data is kept, and Approve never merges locally in place of a required pull request. See docs/reference.md.
- `bakery-cli` has a new help screen with a cake, per-command help (`bakery-cli help start`), typo suggestions, and aligned, coloured output on a terminal. Piped output is unchanged. `npm link` also installs it as `bakery`.
- `bakery-cli doctor` names the server it reached, says whether it's local or remote, and prefixes remote board paths with the host. A missing `pi` now reads as not found when a directory on `PATH` is unreadable.
- `bakery-cli doctor` ends with `INFO` rows: the CLI's path, its `BAKERY_*` variables with secrets hidden, and the server's host, features, active runs, agent models, telemetry and Discord webhook state.
